# Контекст проекта для ChatGPT

Дата снимка: 2026-04-28

Этот файл нужен как стартовый контекст для другого LLM, чтобы он помогал развивать конфигурацию `АгрегаторМаркетплейсов` без догадок. Полный текст всех исходников и метаданных лежит в `CHATGPT_SOURCE_DUMP.md`.

## 1. Что это за проект

- Тип проекта: конфигурация `1С:Предприятие` в формате EDT.
- Имя конфигурации: `АгрегаторМаркетплейсов`.
- Синоним: `Агрегатор маркетплейсов`.
- Режим запуска: `ManagedApplication`.
- Вариант встроенного языка: `Russian`.
- Язык по умолчанию: `Русский`.
- Режим модальности: `DontUse`.
- Совместимость: `8.5.1`.
- Назначение по текущей реализации: ручной учет продаж по маркетплейсам, расчет комиссии/себестоимости/чистой прибыли и построение отчета по накопленному регистру.

## 4. Реализованная бизнес-логика

Основная логика сосредоточена в двух местах:

- `src/Documents/ОтчетОПродажахМаркетплейса/ObjectModule.bsl`
- `src/Documents/ОтчетОПродажахМаркетплейса/Forms/ФормаДокумента/Module.bsl`

Логика формы документа:

- При изменении `Маркетплейс` пересчитываются все строки табличной части.
- При изменении `Количество` пересчитывается текущая строка.
- При изменении `ЦенаПродажи` пересчитывается текущая строка.
- При изменении `Комиссия` тоже вызывается пересчет строки.
- Себестоимость товара подтягивается из `Товар.Себестоимость`.
- Комиссия подтягивается из `Маркетплейс.КомиссияПроцент`.

Формулы в форме:

- `СуммаПродажи = Количество * ЦенаПродажи`
- `Себестоимость = Количество * СебестоимостьЕдиницы`
- `Комиссия = Окр(СуммаПродажи * КомиссияПроцент / 100, 2)`
- `ЧистаяПрибыль = СуммаПродажи - Комиссия - Себестоимость`

Логика проведения документа:

- Проверяется, что выбран `Маркетплейс`.
- Проверяется, что в каждой строке заполнен `Товар`.
- Проверяется, что `Количество > 0`.
- Для каждой строки создается запись регистра `ПродажиМаркетплейсов`.
- При проведении расчет идет не по полям формы, а заново:
- `СуммаПродажи = Количество * ЦенаПродажи`
- `СебестоимостьСтроки = Количество * Товар.Себестоимость`
- `КомиссияСтроки = Окр(СуммаПродажи * Маркетплейс.КомиссияПроцент / 100, 2)`
- `ЧистаяПрибыльСтроки = СуммаПродажи - КомиссияСтроки - СебестоимостьСтроки`

Форма документа `ФормаДокумента`:

- Поля шапки:
- `Дата`
- `Маркетплейс`
- Таблица `Товары`, колонки:
- `LineNumber`
- `Товар`
- `Количество`
- `ЦенаПродажи`
- `СуммаПродажи`
- `Комиссия`
- `Себестоимость`
- `ЧистаяПрибыль`

Свойства колонок:

- `СуммаПродажи` только для чтения.
- `Себестоимость` только для чтения.
- `ЧистаяПрибыль` только для чтения.
- `Комиссия` редактируемая, но при любом пересчете заново вычисляется из процента маркетплейса.

Список документа:

- Динамический список по таблице `Document.ОтчетОПродажахМаркетплейса`.
- Видимые колонки: `Number`, `Date`.

Списки справочников:

- `Товары`: `Артикул`, `Description`, `Себестоимость`.
- `Маркетплейсы`: `Code`, `Description`, `КомиссияПроцент`.
- `Контрагенты`: `Code`, `Description`, `ИНН`.

Командные интерфейсы:

- Общий `Configuration/CommandInterface.cmi` пустой.
- `Configuration/MainSectionCommandInterface.cmi` пустой.
- По структуре проект пока опирается в основном на стандартные команды и стандартные списки.

## 7. Важные нюансы и текущие риски

- В форме документа есть обработчик `ТоварыТоварПриИзменении`, который указан в `Form.form`, но в модуле формы такой процедуры сейчас нет. Это важный дефект текущего состояния.
- Табличная часть документа хранит `Количество` как `Number(15,3)`, а ресурс регистра `Количество` хранится как `Number(15,2)`. Если в проекте нужны тысячные доли, будет потеря точности при записи движений.
- Поле `Комиссия` в форме редактируемое, но при пересчете и при проведении документ все равно берет процент из маркетплейса и пересчитывает комиссию сам. То есть ручное редактирование комиссии фактически не является устойчивым поведением.
- В документе нет реквизита `Контрагент`, хотя справочник `Контрагенты` уже существует.
- Отчет строится только по оборотам регистра и пока не содержит пользовательских фильтров по товару/маркетплейсу, кроме стандартных возможностей СКД.

## 9. Как лучше ставить задачи другому LLM

Хороший формат запроса:

1. Сначала приложить этот файл `CHATGPT_CONTEXT.md`.
2. Если задача затрагивает конкретные объекты, приложить `CHATGPT_SOURCE_DUMP.md`.
3. Просить изменения с точными путями файлов и с учетом метаданных 1С EDT.
4. Просить не придумывать несуществующие объекты и проверять совместимость с уже существующими именами реквизитов и обработчиков.

Готовый шаблон запроса:

```text
Ты помогаешь развивать конфигурацию 1С:Предприятие в формате EDT.

Контекст проекта:
- проект называется "АгрегаторМаркетплейсов"
- встроенный язык: русский
- режим приложения: управляемое приложение
- основная логика сейчас находится в документе "ОтчетОПродажахМаркетплейса", регистре "ПродажиМаркетплейсов" и отчете "ДоходыПоТоварам"

Ниже я приложил:
1. обзор проекта
2. полный дамп исходников и метаданных

Когда будешь предлагать решение:
- опирайся только на существующие объекты проекта или явно отмечай новые
- указывай точные файлы, которые нужно менять
- если меняются метаданные, показывай какие реквизиты/формы/обработчики нужно добавить
- если меняется код BSL, показывай готовые фрагменты кода
- учитывай текущие формулы расчета комиссии, себестоимости и чистой прибыли
- отдельно отмечай возможные проблемы совместимости или дефекты текущей реализации

Задача: <сюда вставить задачу>
```
